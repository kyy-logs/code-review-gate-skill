# 探针共同约束

先于探针专属说明阅读本文件。以下规则适用于所有探针；主流程在每次派发时提供本文件路径，不再在各探针文档中重复这些规则。

## 角色

- 只检查自己的探针。不重跑完整审查流程，也不再派发代理。
- 复用主执行器已确认并交接的审查范围、diff 和材料，以及本代理已读的上下文。

## 证据与 finding

- finding 须说明本次改动如何引入或触发该问题。无关的存量问题单独说明，不纳入本轮 finding 清单及计数。
- 独立只读查询尽量合并，有依赖的查询逐步执行；首次读取源码时保留准确行号和必要上下文。
- 本地搜索限于被审仓库、明确提供的关联目录及依赖坐标对应的缓存路径。从变更文件及已知相关目录检索，按文件类型缩小范围；仅定位文件时只返回路径。提交审查优先用 `git grep <head> -- <paths>` 检索固定目标的受版本控制文件；工作区检索用 `rg`，并从源码搜索中排除审查产物目录。
- 定位调用方时，在限定的源码及测试范围内合并已知方法名、类型名和工厂名检索，复用命中及无匹配范围。仅在具体证据缺口出现新符号或路径线索时扩展；调用方位于所提供仓库之外时记录缺口，继续其余行为链。不反复执行等价检索，不扩大到磁盘根目录或用户目录。

## 输出

- 只写 `{output_root}/active/{slug}/probes/<探针名>.json`，不写共享报告或指标。
- 检查完成后，先等待自己启动的后台任务结束，或停止已不再需要的任务并确认退出；再按 `references/output-schema.md` 校验并保存最终 JSON，随后立即返回交接消息。保存后不再搜索、补证或重复解释 findings。
- 有可靠计时时记录 `duration`；各探针耗时之和不代表本轮墙钟时间。

## 返回消息

仅简述 JSON 路径、实际检查范围和必要限制（含具体证据缺口）。主执行器将相关限制纳入最终报告；不要在返回消息中重复 findings。返回消息不替代 JSON 记录。
