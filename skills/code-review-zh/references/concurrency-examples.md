# 并发交错轨迹示例

以下是构造的执行顺序，不是运行记录。按实际代码选择相关示例，用具体入口、读写位置及契约验证交错；有相似结构不等于存在缺陷。示例不覆盖矩阵全部类型，也不要求输出全部轨迹。

## 1. 检查后执行：分别加锁仍会超卖

契约：库存不得为负。检查与扣减分别持有同一把锁，但扣减时不重检。

```text
初始：stock = 1
A：加锁，读取 stock > 0，解锁。
B：加锁，检查 stock > 0，扣减到 0，解锁。
A：再次加锁，沿用先前结果，扣减到 -1，解锁。
```

错误点：A 的检查结果在操作前过期；单次读写有锁没有保护整个操作。
核对：检查与扣减是否在同一临界区，或操作前有有效重检、条件更新等原子协议。

## 2. 取消与任务结束：释放守卫后旧任务继续写

契约：同一资源只允许一个写任务。此例的取消通知不等待任务退出，新旧任务共用结果。

```text
初始：A 正在执行，busy = true。
用户：请求取消 A。
取消回调：busy = false；A 尚未退出。
用户：再次启动，B 通过 busy 检查并开始执行。
A：继续写共享结果；B 也开始写共享结果。
```

错误点：守卫允许新任务进入时，旧任务仍能影响同一资源。
核对：释放守卫前是否确认旧任务及相关子任务结束，或有实际任务隔离。若旧任务只做隔离计算、不能再写共享状态，不能直接套用此结论。

## 3. 过期回调：旧请求覆盖新结果

契约：页面显示当前选择对应的数据。请求可乱序完成，回调没有检查请求身份。

```text
用户：选择条件 X，启动请求 A。
用户：改选条件 Y，启动请求 B。
B：先返回，页面显示 Y 的结果。
A：后返回，回调无条件更新页面，覆盖为 X 的结果。
```

错误点：回调属于旧请求，却修改当前页面状态。
核对：更新结果前是否校验请求 ID 或版本，或有其他阻止旧回调生效的实际保证；仅请求取消不证明回调不再执行。

## 4. 正确对照：锁内重检阻止过期判断

契约：已有缓存时直接复用。缓存发布和加载决策使用同一把锁。

```text
初始：cache 为空。
A：在锁内读到 cache 为空，解锁。
B：在锁内发布 cache = S，解锁。
A：进入加载决策临界区，重检 cache，发现 S，决定复用而不启动加载。
```

保护点：A 没有沿用旧的空缓存判断；操作决策在锁内使用当前缓存。
排除依据是实际重检及共享锁协议，而不是“代码里有锁”。若只检查另一个标志，仍需证明它能保证原操作的前提成立。
